# TaskPlanner

Настольный планировщик задач на Python. Графический интерфейс сделан на Tkinter, данные хранятся в обычном JSON-файле, внешние библиотеки не нужны.

![Окно TaskPlanner](screenshots/app.png)

## Возможности

- добавление, редактирование и удаление задач;
- поля задачи: название, описание, срок, приоритет (низкий / средний / высокий), категория;
- отметка «выполнена» (двойной клик по задаче или кнопка);
- поиск по названию, описанию и категории;
- фильтры: все, активные, выполненные, просроченные;
- сортировка: по сроку, по приоритету, по названию, сначала новые;
- просроченные задачи подсвечиваются красным, выполненные — серым;
- строка статистики: всего, активных, выполнено, просрочено;
- данные сохраняются автоматически после каждого изменения.

## Быстрый старт

Нужен Python 3.9 или новее. Tkinter обычно уже входит в установку Python
(на Linux, если его нет: `sudo apt install python3-tk`).

```bash
git clone https://github.com/Ag1si/task-planner.git
cd task-planner
python main.py
```

Тот же запуск как модуль: `python -m taskplanner`.

Хотите сразу увидеть приложение с данными — скопируйте пример:

```bash
cp examples/sample_tasks.json data/tasks.json      # Linux / macOS
copy examples\sample_tasks.json data\tasks.json    # Windows
```

## Как пользоваться

1. Заполните форму слева (обязательно только название) и нажмите «Добавить задачу».
2. Чтобы изменить задачу, выберите её в списке — данные появятся в форме. Поправьте их и нажмите «Сохранить изменения».
3. «Выполнена / вернуть» (или двойной клик) переключает статус, клавиша `Delete` удаляет выбранную задачу.
4. Срок вводится в формате `ДД.ММ.ГГГГ`, например `31.12.2026`; поле можно оставить пустым.

## Структура проекта

```
task-planner/
├── main.py                 # точка входа
├── taskplanner/
│   ├── models.py           # Task, Priority, разбор и форматирование дат
│   ├── storage.py          # JsonStorage: чтение и запись файла
│   ├── service.py          # TaskService: логика, фильтры, сортировка, статистика
│   └── gui.py              # окно на Tkinter / ttk
├── tests/                  # unit-тесты (unittest)
├── examples/
│   └── sample_tasks.json   # пример данных
├── data/                   # здесь создаётся tasks.json (не попадает в git)
└── screenshots/
```

Проект разделён на слои: интерфейс ничего не знает о файлах, а логика и хранение не зависят от Tkinter, поэтому их можно тестировать отдельно.

## Формат данных

Задачи лежат в `data/tasks.json`:

```json
{
  "version": 1,
  "tasks": [
    {
      "id": "a1b2c3d4",
      "title": "Сдать курсовую работу",
      "description": "Оформить список литературы",
      "due_date": "2026-12-26",
      "priority": 3,
      "category": "Учёба",
      "done": false,
      "created_at": "2026-11-01T10:00:00"
    }
  ]
}
```

Файл записывается атомарно (через временный файл), так что сбой посреди записи не испортит данные.
Если файл всё же оказался повреждён, он переименовывается в `tasks.json.corrupt`, а приложение стартует с пустым списком.
Старый формат (просто список с полями `title`, `description`, `due_date`) тоже читается.
